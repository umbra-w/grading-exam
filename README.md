# Grading_exam

> Electron 桌面端的 AI 阅卷助手（原名 YJAI · 阅卷AI 的开源复刻版）。
> 老师在**自己拥有账号的阅卷平台**上，由软件自动完成"看题目 → 评学生答案 →
> 把分数填进输入框 → 提交"这一串操作。**全部数据落本机，无后端。**

---

## ⚠️ 先读这一段：它现在能用吗

**不能直接拿去阅卷。** 这是一个**可继续开发的工程底座**，不是可用阅卷软件。

| 能力 | 状态 |
|---|---|
| 纯逻辑层（评分解析、复核队列、坐标换算、填分状态机、聚合口径、导出、学情解读） | ✅ 861 项单测覆盖（32 套件） |
| 界面 | ✅ 可用（可用 Edge 无头渲染验证布局与配色） |
| 单题 AI 批改 | ✅ 可用（需要自己的 API Key） |
| 整卷聚合 / 导出 / 学情分析 | ✅ 可用（**粘贴录入** 或 **批量图片识别答案 → 自动判分** → 汇总） |
| 批量上传答卷图片并由 AI 识别 | 🟡 **链路已接通**（F3.4）：空白卷拦截 → 逐张视觉识别 → 逐题对齐 → 客观题本地比对（零 token）/ 主观题 AI 评分 → 成绩行回填粘贴区。⚠ 视觉调用与 AI 评分**未在真机验证**（需自己的 API Key + 视觉模型），识别与判分结果全部先列出供人工核对 |
| 自动填分 / 自动提交（连续阅卷） | 🟡 代码路径完整，但**未在真实平台验证过** |
| 免安装版（portable / zip） | ✅ 可产出：`pnpm dist` 实测生成单文件便携版 exe 与免安装 zip。⚠ 本机 Electron 起不来（见下），**产出的 exe 从未运行过**，双击能否启动需真机确认 |

**为什么不能声称"支持主流阅卷平台"**：平台各异，首个真实平台仍需约
0.5~1 天适配。软件不探索、不猜测，靠你在页面上**手动拾取**输入框与提交按钮。

> **未验证 ≠ 不可用，但更不等于已验证。**
> 在任何机器上跑过真实平台之前，**不要开启自动提交**（`top` 模式会真的按下
> 平台的提交按钮）。

## 三条不可逾越的边界

写在 [SPEC.md](SPEC.md) §3.6，带禁语清单：

| 边界 | 含义 |
|---|---|
| **只服务本人账号** | 不得用于代他人阅卷、不得用于未授权平台 |
| **不声称通吃平台** | 见上 |
| **客观题与主观题分开报告** | 客观题是确定性比对；主观题是统计一致性。**永远不合并成一个"准确率"数字** |

## 快速开始

### 环境要求

| 项 | 版本 |
|---|---|
| Node.js | >= 20.19.0（开发用 v24） |
| Python | 3.10+（仅评测轨与部分检查需要） |
| pnpm | 任意近期版本（仓库用 corepack shim） |
| 系统 | Windows（当前只在 Windows 上开发） |

```bash
pnpm install
```

### 构建与验证

```bash
pnpm typecheck     # 双 project 类型检查，两侧都必须 exit=0
pnpm test          # vitest：861 项
pnpm verify:all    # 上面这些 + IPC 对账 + 结构树 + 数据集 + 契约冻结 + 评测自测
pnpm build         # typecheck + 三端构建
pnpm dev           # 开发模式
```

界面验证（**不需要能启动 Electron**）：

```bash
pnpm ui:verify     # Edge 无头渲染 → 逐面板截图 → 断言 → 对比度 + 像素统计
```

> **本机 Electron 起不来**：`app.whenReady()` 阶段崩溃，退出码 `0xC0000005`，
> 已试过 9 种 flag 组合全部失败。详见 [BLOCKERS.md](BLOCKERS.md) B3。
> 所以窗口/CDP/拾取行为**必须上真机验证**，本地做不到，本项目也不假装能验。

### 运行

**不需要安装。** 两种形态都用 `pnpm dist` 产出，在 `release/` 下：

| 形态 | 怎么用 | 取舍 |
|---|---|---|
| `Grading_exam-0.1.0-便携版.exe` | **双击直接运行** | 最省事。但它每次运行会把自己解压到系统临时目录，启动稍慢 |
| `Grading_exam-0.1.0-免安装.zip` | 解压到任意目录，运行里面的 `Grading_exam.exe` | 目录稳定、启动更快；适合长期放一个固定位置 |

启动后在「设置」里填自己的 AI 服务（API 地址 / Key / 模型名，支持
OpenAI 兼容接口）。

**数据存在哪**（启动日志会打印，可在底部日志栏看到）：

| 形态 | 数据位置 |
|---|---|
| 便携版 exe | **exe 所在目录下的 `data\`** —— 整个目录拷走即可带走全部数据（含 API Key、拾取配置、复核队列） |
| 解压目录版 | 同上，数据在解压目录的 `data\` 里 |
| 开发运行（`pnpm dev`） | 系统用户数据目录 `%APPDATA%\grading-exam`，不随程序目录移动 |

> 便携版的代价：若把 exe 放在系统临时目录里运行，那个目录随时会被清理，
> 数据会同生共死。想要稳定就用 zip 版解压到固定目录。
> 也可以用环境变量 `GRADING_EXAM_DATA_DIR` 显式指定数据目录。

> ⚠️ 产出的 exe **未签名**，Windows SmartScreen 会提示"未知发布者"。
> 这是开源项目未购买代码签名证书的正常现象，但要知道这一点。

## 工作流

```
              ┌─ 单题批改 ──→ 复核队列（低置信度必须人工确认）
答卷图片 ─┬─┤
          │ └─ 整卷阅卷 ─┬→ 批量图片识别 ─→ 自动判分（客观本地比对 / 主观 AI）─┐
          │              ├→ 粘贴录入成绩 ────────────────────────────────────┤
          │              └──────────────── 校验解析 → 汇总统计 → 学情分析 → 导出
          └─ （识别与判分结果一律先列出供人工核对，不会静默进入报表）
                          Excel / Markdown
```

**整卷面板的两路入口**（结果互通）：

1. **批量图片导入**：多选答卷照片 → 空白卷本地拦截（不耗 token）→
   逐张视觉识别姓名/考号与逐题答案 → 逐题对齐（对不上的**保留原文**不丢弃）→
   「先试一张」确认效果后再识别全部 → 人工核对识别草稿。
2. **粘贴录入**：直接粘 `姓名,考号,分数,…` 文本，逐条校验。

识别完成后可点「自动判分」：客观题本地归一化比对（零 token，缺参考答案的题
标"无法判分"，**绝不交给模型猜**）、主观题走 AI 按评分要点评分；
判出的成绩行一键回填粘贴录入区，仍要过「校验并解析」那道校验才进汇总。
两个入口共用同一份题目定义与汇总口径，不存在第二条统计路径。

⚠ 诚实边界：视觉识别与 AI 评分**未在真机验证过**（需要你自己的 API Key
与支持视觉的模型）；所有识别/判分结果都先列出供人工核对。

整卷阅卷面板里有可直接复制的录入示例。

## 项目结构

```
src/
├─ shared/     渲染层与主进程共用，唯一真源（IPC 契约 + 选择器生成）
├─ main/       主进程：AI 层 / 自动化层 / 解析与导出
├─ preload/    contextBridge 桥（泛型派发器）+ 注入阅卷页的拾取脚本
└─ renderer/   React 面板 + 设计令牌
```

分层与"为什么这么分"见 [ARCH.md](ARCH.md)；纯逻辑与薄绑定的隔离约束
（两套测试从两个方向把守）见 [AGENTS.md](AGENTS.md) §4.4。

**核心设计**：能测试的纯逻辑（评分解析、复核判定、坐标换算、填分重试状态机、
聚合口径、导出、学情建议）与无法本地测试的薄绑定（CDP、浏览器窗口）
严格分离 —— 这不是偏好，是唯一可行的验证手段。

## 数据与隐私

- 全部数据落本机，无后端、无遥测。
- 答卷原始图片与标注数据含个人信息，**已在 `.gitignore` 中禁止入库**
  （`data/raw/`、`data/derived/`）。请勿把真实答卷提交到仓库。
- 评测用数据集不在本仓库内（外部路径引用）。

## 已知限制

1. **未在真实阅卷平台上验证过**。自动填分/提交的执行层代码完整，但需要真机验证。
2. **置信度阈值 `0.75` 是未经标定的经验值**。所有质量阈值同理 ——
   它们来自工程判断，不是实测标定结果。
3. **主观题准确率尚未测量**。需要教师双评数据（评测轨 E2），
   那需要真实教师资源，不是代码能解决的。
4. **批量图片识别的视觉调用与 AI 判分未在真机验证过**（链路已接通，
   需要你自己的 API Key 与支持视觉的模型；所有结果先列出供人工核对）。
   空白卷阈值（灰度标准差 < 6）同样是未标定经验值。
5. **首个真实平台需要适配**，约 0.5~1 天。

## 贡献

动代码前请读完 [AGENTS.md](AGENTS.md)。其中两条最容易踩：

1. **新功能一律先把纯逻辑抽出来测，再接薄绑定**（本机 Electron 起不来）。
2. **验证全绿立刻提交**（§8.0）。一个"已通过 831 项单测"的状态是花了几十分钟
   挣来的，留在工作区就会被后续改动弄脏。

验证脚本自己也会失效（曾出现"截图不存在 → 跳过像素检查 → 报全部通过"），
所以新增检查时**必须用注入故障的方式验证它会真红**。
